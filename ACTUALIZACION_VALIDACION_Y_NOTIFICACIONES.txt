===========================================================
 ACTUALIZACION - Flujo de validacion por foto + notificaciones
 Fecha: 18/10/2026
===========================================================

Este cambio agrega el flujo completo de estados de las
identificaciones (PENDIENTE / VALIDADA / RECHAZADA),
validacion POR FOTOGRAFIA desde la web, notificaciones
in-app, y un mapa Leaflet/OpenStreetMap en la web.

Al bajar estos cambios (git pull) tu entorno local NO queda
listo solo. Hay que: aplicar DOS migraciones nuevas a la
base, reiniciar PowerSync, instalar una dependencia nueva en
la web, regenerar el codigo de la app y reinstalarla.

Segui los pasos en orden.


-----------------------------------------------------------
 1) BASE DE DATOS - aplicar migraciones 005 y 006
-----------------------------------------------------------
Las migraciones son archivos .sql sueltos; NO se aplican
solas. Aplicalas UNA sola vez, en orden, contra el Postgres
que corre en Docker (contenedor powersync_backend-pg-db-1).

Antes de aplicar, confirma que ya tenes las migraciones
002 y 004 (columnas de validacion en observations). Si tu
base es vieja, aplica primero 001..004.

Desde la carpeta api/backend (PowerShell):

  # 005 - tablas notifications y device_tokens
  Get-Content migrations/005_add_notifications.sql -Raw |
    docker exec -i -e PGPASSWORD=KospiaDB2026 powersync_backend-pg-db-1 `
    psql -U postgres -d postgres

  # 006 - columnas de validacion POR FOTO en observation_photos
  Get-Content migrations/006_add_photo_validation.sql -Raw |
    docker exec -i -e PGPASSWORD=KospiaDB2026 powersync_backend-pg-db-1 `
    psql -U postgres -d postgres

Verificar que quedaron bien:

  docker exec -e PGPASSWORD=KospiaDB2026 powersync_backend-pg-db-1 `
    psql -U postgres -d postgres -c "\d public.notifications"
  docker exec -e PGPASSWORD=KospiaDB2026 powersync_backend-pg-db-1 `
    psql -U postgres -d postgres -c "\d public.device_tokens"
  docker exec -e PGPASSWORD=KospiaDB2026 powersync_backend-pg-db-1 `
    psql -U postgres -d postgres -c "\d public.observation_photos"

En observation_photos deben aparecer las columnas:
validation_status, validation_comment, validated_species_id,
validated_at, validated_by.


-----------------------------------------------------------
 2) POWERSYNC - reiniciar para recargar sync-config.yaml
-----------------------------------------------------------
Se agrego la bajada de la tabla notifications y las columnas
nuevas de observation_photos a las reglas de sincronizacion
(api/backend/powersync/sync-config.yaml). Hay que reiniciar
el servicio para que recargue las reglas:

  docker restart powersync_backend-powersync-1

Verificar que arranco sano (debe decir "Service started" y
quedar healthy, sin "Invalid SQLite cast"):

  docker logs --tail 20 powersync_backend-powersync-1


-----------------------------------------------------------
 3) BACKEND (api/backend) - solo reiniciar
-----------------------------------------------------------
No cambiaron dependencias de Python. Solo hay que reiniciar
Flask para que tome las rutas nuevas (notifications y los
endpoints de validacion por foto):

  cd api/backend
  .venv\Scripts\activate
  py app.py


-----------------------------------------------------------
 4) WEB (web) - dependencia nueva: Leaflet
-----------------------------------------------------------
Se agregaron leaflet + react-leaflet (mapa OpenStreetMap,
gratis, sin API key). Sincroniza con el lock:

  cd web
  npm install

Validar:

  npm run build      (tsc -b && vite build, sin errores)


-----------------------------------------------------------
 5) APP FLUTTER (app) - regenerar codigo + reinstalar
-----------------------------------------------------------
El esquema local subio a databaseVersion 8 (columnas de
validacion por foto + tabla notifications). NO cambiaron
paquetes de pub, pero hay que regenerar el codigo drift:

  cd app
  flutter pub get
  dart run build_runner build --delete-conflicting-outputs

IMPORTANTE: reinstala la app en el dispositivo/emulador para
resetear el estado local de PowerSync (nuevo esquema v8).
Una reinstalacion limpia evita inconsistencias de esquema
local y fuerza una bajada fresca con las columnas nuevas.


-----------------------------------------------------------
 RESUMEN RAPIDO (copiar y pegar)

  # 1) migraciones (desde api/backend)

-----------------------------------------------------------
 NOTAS
-----------------------------------------------------------
- Las migraciones NO son idempotentes (igual que 002/004):
  aplicarlas una sola vez por base. Solo reaplicar si recreas
  el volumen de Postgres.
- Cada uno trabaja con su propia base local y sus datos de
  prueba. NO se pasa la base entre integrantes: el esquema se
  reproduce con las migraciones.
- Si algo falla despues de actualizar, avisá antes de seguir
  trabajando asi lo revisamos.
