1. RESUMEN DE LA INTEGRACION
----------------------------

Se integraron los desarrollos de ambos integrantes del proyecto Kospia,
incluyendo Flutter, Flask, PostgreSQL, PowerSync y el panel web React.

La integracion incorpora:

- Administracion del catalogo de especies desde el panel web.
- Edicion de especies y sus rasgos utilizados para la identificacion.
- Administracion de descripciones, iconos e imagenes de ayuda para
  las opciones del cuestionario.
- Mejoras en la identificacion de especies mediante sus rasgos.
- Sincronizacion offline-first mediante PowerSync.
- Observaciones y fotografias asociadas a los usuarios.
- Mejoras en el manejo de la cola local de subida de fotografias.
- Ajustes en autenticacion y administracion de observaciones.

2. AYUDA PARA LAS OPCIONES DEL CUESTIONARIO
-------------------------------------------

Desde el panel web se pueden administrar:

- La descripcion de una opcion.
- El icono o imagen representativa de una opcion.
- Una galeria de imagenes de ayuda.

Ejemplo:
Una opcion como "Subarbusto" puede incluir una descripcion y fotografias
que ayuden al usuario a comprender su significado.

En Flutter, las opciones pueden mostrar un icono de informacion en la
esquina superior derecha. Al tocarlo, se abre una ventana emergente
con la descripcion y un carrusel de imagenes de ayuda.

Los cambios del catalogo se distribuyen mediante PowerSync cuando
existe conectividad y la sincronizacion funciona correctamente.

En modo offline, la aplicacion utiliza los datos ya sincronizados.
Las imagenes requieren estar disponibles en cache o almacenamiento local
para poder visualizarse sin conexion.

7. APLICACION FLUTTER
---------------------

Se incorporaron:

- Mejoras en el motor de identificacion por rasgos.
- Visualizacion de ayuda contextual para las opciones.
- Manejo de iconos e imagenes de opciones.
- Escritura transaccional de observaciones y su cola local.
- Manejo de respuestas HTTP durante la subida de fotografias.

Comportamiento de subida de adjuntos:

- HTTP 2xx: se elimina el elemento pendiente de la cola.
- HTTP 404: el elemento permanece pendiente.
- HTTP 401/403: se detiene el procesamiento conservando la cola.
- Otros errores HTTP: se conserva el elemento para reintento.

El reintento no implica necesariamente ejecucion periodica automatica.
La API de almacenamiento debe manejar correctamente los reintentos
para evitar duplicaciones.

Despues de actualizar:

1) Ingresar a la carpeta app.
2) Ejecutar flutter pub get.
3) Ejecutar flutter analyze.
4) Ejecutar flutter test.
5) Probar el flujo completo de identificacion y observaciones.

El archivo generado app_database.g.dart fue comparado entre ambas
versiones y su contenido resulto identico, ignorando finales de linea.
